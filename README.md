# Attribution Engine

**"`git bisect` for multi-agent AI systems."**

When a multi-agent pipeline produces a bad output, existing tools show you
the full trace but not *which agent actually caused the failure*. This
project builds that missing piece: automatic root-cause attribution for
multi-agent failures.

## The pipeline

A 4-agent LangGraph system that researches a topic and writes a report:

```
Researcher (RAG: search + rerank tools)
    ↓
Analyst (synthesizes findings)
    ↓
Writer (drafts the report)
    ↓
Critic (scores retrieval/grounding/generation quality, routes accordingly)
```

The Critic doesn't just approve-or-reject — it diagnoses **which stage**
actually failed, using three metrics inspired by RAGAS:

- **Retrieval quality** (context precision/recall) — did the Researcher
  find relevant docs? If not, route back to the Researcher.
- **Grounding quality** (faithfulness) — is the Analyst's synthesis actually
  supported by what was retrieved? If not, route back to the Analyst.
- **Generation quality** (coherence/relevance) — does the Writer's draft
  faithfully reflect the analysis? If not, route back to the Writer.

Checks run in that priority order deliberately — retrieval failures make
grounding look bad too as a downstream symptom, not a separate root cause,
so the earliest real failure is what gets caught, not every stage that
happens to look bad as a side effect.

Every routing decision is logged in `routing_history` — across enough runs,
this becomes a real, labeled attribution dataset generated by the
pipeline's own reasoning.

Early skeleton — deterministic stub nodes verify the graph structure

## Setup

```bash
python -m venv venv
./venv/Scripts/activate  # or source venv/bin/activate on Mac/Linux
pip install -r requirements.txt
python -m src.graph       # run the pipeline once
python -m pytest tests/   # run the test suite
```

## Roadmap

- [ ] Real LLM calls in each node (currently deterministic stubs)
- [ ] Real RAG: Researcher's `search`/`rerank` tools over an actual doc set
- [ ] OTel instrumentation on every node + the Critic's routing decisions
- [ ] Ablation-based attribution (swap one agent's output to a known-good
      version, see which swap fixes the outcome) as a second, deterministic
      attribution method alongside the Critic's live routing
- [ ] LLM-judge attribution as a comparison baseline
- [ ] Synthetic benchmark: 20-30 cases with deliberately injected failures
      and known ground-truth culprits, to score both attribution methods
- [ ] Adversarial test: plant a compromised agent, confirm attribution
      correctly names it
- [ ] Dockerize, containerized end to end
